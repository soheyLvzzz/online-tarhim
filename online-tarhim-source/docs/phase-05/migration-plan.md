# برنامهٔ Migration انتشار اول

## تصمیم

برای نسخهٔ لندینگ ثابت با تماس مستقیم، دیتابیس نداریم؛ بنابراین schema پایگاه داده، جدول، index، constraint دیتابیس، migration SQL یا Prisma و seed پایگاه داده ایجاد نمی‌شود. این وضعیت «عدم نیاز مستدل برای این انتشار» است، نه Migration انجام‌شده یا زیرساخت پایگاه دادهٔ آماده.

## وضعیت اجرا

| مورد | وضعیت |
| --- | --- |
| دیتابیس هدف | تعریف نشده؛ برای این انتشار لازم نیست. |
| Migration دیتابیس | ندارد؛ هیچ فرمان ساخت، تغییر یا حذف دیتابیس اجرا نمی‌شود. |
| انتقال دادهٔ سامانهٔ قبلی | در دامنهٔ فعلی تعریف نشده؛ انجام‌شده اعلام نمی‌شود. |
| محتوای اولیه | متن‌ها و آرایه‌های ثابت فعلی؛ تأیید داده‌های انتشار در فاز ۱۳. |
| تغییر ساختار محتوای فرانت‌اند | در این فاز انجام نشد؛ مدل محتوای موجود مستند شد. |

## تغییر محتوا و بازگشت

تغییر محتوای ثابت، اصلاح فایل سورس و ساخت مجدد است و Migration دیتابیس محسوب نمی‌شود. خروجی HTML/CSS/JS و دارایی‌ها باید به‌عنوان یک نسخهٔ هماهنگ منتشر شوند. برای بازگشت از انتشار، نسخهٔ قبلی فایل‌ها بازیابی می‌شود؛ برنامه و اجرای پشتیبان‌گیری/بازگشت در فازهای استقرار ثبت می‌شوند. در این فاز هیچ فایل هاست یا داده‌ای حذف یا جابه‌جا نشد.

## زمان نیاز به طراحی جدید

اگر ثبت فرم، حساب کاربری، پنل مدیریت، ذخیرهٔ سفارش، پرداخت یا مدیریت مراسم وارد محدوده شود، مدل موجود برای آن کافی نیست. پیش از اتصال قابلیت جدید، مدل داده و قرارداد API همان قابلیت، قواعد اعتبارسنجی و دسترسی، سپس Migration و روش بازیابی تهیه شوند. وجود مدل استاتیک حاضر مجوز ساخت خودکار دیتابیس یا اتصال سرویس خارجی نیست.
