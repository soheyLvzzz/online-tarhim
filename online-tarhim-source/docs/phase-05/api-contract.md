# قرارداد ارتباطات انتشار اول

## API سروری

این انتشار endpoint کاربردی ندارد. هیچ GET/POST/PUT/PATCH/DELETE برای سفارش، کاربر، مقاله، مراسم، پیام یا پرداخت تعریف یا پیاده‌سازی نمی‌شود. بنابراین بدنهٔ درخواست/پاسخ JSON، وضعیت‌های موفقیت/خطای API، صفحه‌بندی، توکن احراز هویت و مجوز endpoint برای این دامنه موضوعیت ندارند. این موارد برای سامانهٔ کامل در آینده باید طراحی شوند.

دریافت index.html، باندل JavaScript/CSS، تصاویر، فونت و SVG از هاست، دریافت فایل استاتیک است و API کسب‌وکار محسوب نمی‌شود. رفتار HTTP خطاهای فایل/دامنه به میزبانی وابسته است و در این سند آزموده‌شده اعلام نمی‌شود.

## مرز تماس

لینک‌های tel و mailto به برنامهٔ دستگاه واگذار می‌شوند. فعال‌کردن آن‌ها در سایت سفارش یا پیام ذخیره نمی‌کند و تأیید موفقیت تماس یا تحویل ایمیل به سایت برنمی‌گرداند. در این فاز به شمارهٔ واقعی جدید یا سرویس ایمیل/پیامک متصل نشدیم.

## قرارداد رویدادهای داخلی موجود

این جدول صرفاً ارتباط callbackهای موجود فرانت‌اند را مستند می‌کند؛ این رویدادها endpoint نیستند، درخواست شبکه ارسال نمی‌کنند و به‌تنهایی مقصد عملیاتی ایجاد نمی‌کنند.

| رویداد | detail | مقادیر موجود | مصرف فعلی |
| --- | --- | --- | --- |
| tarhim:navigate | { target: string } | home، live، memorial، request، contact، blog | home به ابتدای صفحه اسکرول می‌کند؛ مقصدهای دیگر با صدور رویداد ساخته نمی‌شوند. |
| tarhim:request-plan | { planId: string } | simple، special، custom | انتخاب پلن را اعلام می‌کند؛ درخواست در سرور ثبت نمی‌شود. |
| tarhim:service-details | { serviceId: string } | ceremony، host، live، poster، video، archive | اعلام انتخاب خدمت؛ صفحهٔ جزئیات هنوز وجود ندارد. |
| tarhim:view-archive | { ceremonyId: string } | ceremony-1 تا ceremony-4 | انتخاب کارت نمایشی؛ پخش ویدیو ندارد. |
| tarhim:read-article | { articleId: string } | online-ceremony-guide، remembrance-traditions، digital-memorial، platform-updates | انتخاب عنوان؛ متن کامل و صفحهٔ مقاله ندارد. |
| tarhim:social | { platform: string } | instagram، whatsapp | اعلام انتخاب آیکون؛ نشانی حساب متصل نیست. |

پیاده‌سازی فعلی callbackها در main.tsx و کامپوننت‌های مربوط قرار دارد. این رویدادها ورودی قابل اعتمادِ یک سرور نیستند و در آینده نباید جای اعتبارسنجی یا مجوز سمت سرور استفاده شوند.

## اعتبارسنجی و مجوزها

برای این انتشار ورودی فرم یا عملیات سروری نداریم؛ endpoint و سیستم مجوز صوری اضافه نمی‌شود. TypeScript خطاهای نوعی سورس را کنترل می‌کند و اعتبارسنجی امنیتی دادهٔ دریافتی نیست. اگر ورودی/سرویس به دامنه اضافه شد، قرارداد آن باید قبل از پیاده‌سازی تعیین کند چه فیلدهایی مجازند، چه نقش‌هایی دسترسی دارند و خطاها چگونه گزارش شوند.

## موارد آگاهانهٔ باز

کاربر اعلام کرده از دکمه‌های بی‌مقصد آگاه است و هدف فعلی، آنلاین‌شدن ظاهر لندینگ است. این اعلام، ثبت استثنای شناخته‌شده برای نسخهٔ اولیه است؛ به معنی کامل‌شدن قابلیت یا تغییر خودکار همهٔ دکمه‌ها به تماس نیست. وضعیت و رفتار آن‌ها در فاز ۹ و تصمیم انتشار در مراحل مربوط ثبت می‌شود. در این فاز ظاهر، شماره‌ها و callbackها تغییر نکردند.

## یادداشت افزودهٔ فاز ۷

health.json که در فاز ۷ هنگام build تولید می‌شود سند فایل‌های عمومی است و API کاربردی نیست. شامل اندازه/checksum فایل‌ها و شناسهٔ نسخه است؛ وضعیت سرور، دیتابیس و قابلیت سفارش را تضمین نمی‌کند. قرارداد نبود API سروری در انتشار اول همچنان برقرار است.
