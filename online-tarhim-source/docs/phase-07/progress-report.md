## فایل‌های تغییرکرده

- scripts/verify-static-build.mjs: بررسی build و تولید سند نسخه.
- scripts/check-live.mjs: کنترل HTTP و همسانی فایل‌های نسخهٔ آپلودشده.
- scripts/test_static_infrastructure.mjs: پنج تست کنترل زیرساخت استاتیک.
- package.json: افزودن healthcheck و verify:static و اتصال بررسی خروجی به build؛ افزودن تست‌های جدید به test.
- docs/phase-06/closure-report.md: بستن مستند فاز قبل.
- اسناد و راهنمای ادامه؛ src، CSS، دارایی‌های موجود و ظاهر صفحه تغییر نکردند.

## بررسی انجام‌شده

npm run check موفق بود: TypeScript، پنج تست هوک، پنج تست جدید زیرساخت و دو تست Python پیش‌نمایش؛ جمعاً ۱۲ تست. npm run build موفق بود و برای production شناسهٔ cf1ad40cd68a8771 با ۳۴ فایل عمومی تولید شد. هیچ وابستگی جدید نصب نشد.

پنج تست جدید شامل بررسی deployment شبیه‌سازی‌شده و تشخیص تغییر بایت، رد فونت مفقود، رد noindex در production و .env در خروجی عمومی، اعلام خطا برای manifest مفقود و جلوگیری از خروج درخواست‌ها از پوشهٔ مقصدند. این‌ها تست مرورگر یا تست امنیت کامل نیستند.

اجرای اولیهٔ healthcheck برای https://onlinetarhim.com/ به HTTP 404 برای health.json رسید. چون سند جدید هنوز به هاست داده نشده بود، این شکست مورد انتظار است و مشکل جدید در رابط سایت ادعا نمی‌شود. موفقیت نهایی آنلاین از اجرای محلی یا تست mock نتیجه گرفته نمی‌شود.

## خروجی‌های ضروری و شرط پایان

زیرساخت پایهٔ متناسب با نسخهٔ استاتیک به‌صورت ابزار اجرایی، تست‌ها و فایل health.json آماده است. گزارش بررسی اتصال‌ها شامل نتیجهٔ محلی و وضعیت بازِ کنترل هاست است. راهنمای بارگذاری در handoff-guide.md قرار دارد. پس از بارگذاری بستهٔ ریشه و staging، healthcheck واقعی باید برای هر دو موفق شود یا هر اختلاف مشخص و رفع شود؛ تا آن زمان فاز ۷ از نظر تأیید هاست باز می‌ماند. وارد فاز ۸ نمی‌شویم.

## دادهٔ موردنیاز کاربر

دامنه، مسیر هاست و مخزن قبلاً مشخص‌اند. این فاز به شمارهٔ تماس، رمز هاست، توکن GitHub، اطلاعات دیتابیس یا محتوای تازه نیاز ندارد. تنها اقدام وابسته، بارگذاری بسته‌های آماده توسط خود کاربر و اعلام پایان آپلود است. تغییر طرح، تکمیل دکمه‌ها یا تنظیم سرویس خارجی در این مرحله درخواست نشده است.
