# زیرساخت پایهٔ نسخهٔ استاتیک آنلاین ترحیم

دامنهٔ مصوب همان انتشار اول معرفی و تماس مستقیم است؛ معماری سروری سامانهٔ نهایی در این فاز ساخته نمی‌شود. هیچ کد سکشن، استایل، مقصد دکمه یا دادهٔ نمایشی تغییر نکرده است.

## جریان ساخت

npm run build اکنون TypeScript، ساخت تمیز Vite با --emptyOutDir و scripts/verify-static-build.mjs را اجرا می‌کند. کنترل آخر، موجودبودن و غیرخالی‌بودن فایل‌ها، ارجاع‌های HTML/CSS و تصاویر محلی JavaScript، زبان فارسی و RTL، link آیکون و تنظیم robots متناسب با محیط را بررسی می‌کند. وجود .env یا پوشه‌هایی مانند src/docs/node_modules/.git در خروجی باعث شکست بررسی می‌شود. این کنترل جای ممیزی کامل secret یا امنیت را نمی‌گیرد.

اگر بررسی موفق باشد، dist/health.json تولید می‌شود. این فایل تنها سند نسخهٔ استاتیک است: نام سرویس، محیط، شناسهٔ ساخته‌شده از فهرست فایل‌ها، اندازه و SHA256 هر فایل عمومی. در آن وضعیت فرضی healthy، اتصال دیتابیس یا موفقیت تراکنش ثبت نمی‌شود. اطلاعات بازدیدکننده یا secret ندارد و در دسترس عمومی است.

## بررسی نسخهٔ آپلودشده

فرمان npm run healthcheck -- https://onlinetarhim.com/ فایل health.json را از همان مسیر می‌گیرد، ساختارش را کنترل می‌کند و حداکثر چهار درخواست همزمان برای فایل‌های فهرست‌شده می‌فرستد. اندازه و SHA256 فایل‌های واقعی با سند مقایسه می‌شوند. برای پوشهٔ آزمایشی از نشانی https://onlinetarhim.com/staging/ استفاده می‌شود. فایل‌های یک محیط نمی‌توانند به نشانی بیرون از پوشهٔ انتخاب‌شده ارجاع بدهند.

اگر سند یا فایل مفقود باشد، HTTP خطا بدهد، فایل متفاوت یا سند نامعتبر باشد، فرمان با exit code غیرصفر و گزارش خطا تمام می‌شود. موفقیت فقط همسانی فایل‌های عمومی و دسترسی HTTP را نشان می‌دهد؛ صحت رابط مرورگر، عملکرد دکمه‌ها، امنیت هاست یا آماده‌بودن backend را نشان نمی‌دهد. manifest به‌تنهایی مرجع اعتماد امنیتی نیست؛ اگر سرور مصالحه شده باشد می‌تواند هم فایل و هم manifest را عوض کند.

نسخهٔ ریشه و staging به علت تفاوت robots، شناسه و checksum متفاوت دارند. سند نسخهٔ ریشه نباید روی staging کپی شود و برعکس. خروجی health پس از هر تغییر فایل باید دوباره توسط build/verify ساخته شود؛ ویرایش دستی فایل روی هاست بدون بازسازی، باعث اختلاف می‌شود.

## خطا و Logging

کنترل‌های ساخت و بررسی آنلاین، خطا را به‌جای پنهان‌کردن با خروجی JSON و exit code 1 اعلام می‌کنند؛ موفقیت هم JSON شامل شناسهٔ نسخه و تعداد فایل‌های بررسی‌شده دارد. این گزارش‌ها در ترمینال اجراکننده‌اند و سرویس جمع‌آوری لاگ بازدیدکننده یا analytics اضافه نشده است. درخواست‌های واقعی فایل و خطاهای وب‌سرور همچنان به زیرساخت cPanel مربوط‌اند؛ دسترسی به لاگ حساب یا تغییر تنظیمات آن توسط عامل انجام نشده است.

برای برنامهٔ Node/API که وجود ندارد، middleware خطا و Logger صوری ساخته نشده است. Error Boundary و گزارش‌گیری خطاهای render مرورگر نیز در این نوبت اضافه نشده‌اند؛ کنترل ایستای ساخت همهٔ خطاهای اجرای JavaScript را پیدا نمی‌کند. فایل .htaccess، خطای 404 اختصاصی یا تنظیمات سرور بی‌اجازه تغییر نکرده است.

## فایل و ذخیره‌سازی

public/assets و public/fonts محل دارایی‌های عمومی ثابت‌اند؛ Vite آن‌ها را به dist می‌برد. آپلود بازدیدکننده، فایل خصوصی و فضای ذخیره‌سازی ابری در دامنهٔ این نسخه نیستند. قواعد فایل خصوصیِ کنترل ساخت صرفاً جلوی برخی اشتباه‌های بسته‌بندی را می‌گیرند، نه اینکه همهٔ فایل‌های عمومی را از نظر محرمانگی بازبینی کنند.

## اجرا و مرز محیط

ابزارها فقط برای توسعه و کنترل‌اند؛ هاست همچنان فایل استاتیک سرو می‌کند و به اجرای Node روی cPanel نیاز ندارد. Node و TypeScript موجود حفظ شده‌اند و وابستگی جدیدی نصب نشده است. root و staging باید با بستهٔ صحیح خودشان به‌روزرسانی شوند. تمام ورودی‌های ZIP زمان واقعی دارند؛ فایل‌ها 0644 و پوشه‌ها 0755 هستند. برای حل مشکل هاست، این ابزار دسترسی فایل‌ها یا امنیت سرور را خودکار تغییر نمی‌دهد.
