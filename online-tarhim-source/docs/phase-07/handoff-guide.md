# تحویل و بررسی فاز ۷

۱. بستهٔ phase07-public-html.zip فقط فایل‌های عمومی آمادهٔ ریشه است. داخل public_html استخراج و فایل‌های هم‌نام جایگزین شوند. از index.html فعلی پیش از جایگزینی نسخهٔ پشتیبان روی رایانه نگهداری شود. ZIP در ریشه پوشهٔ اضافی ندارد و robots آزمایشی وارد نسخهٔ اصلی نمی‌شود.

۲. بستهٔ phase07-staging.zip داخل public_html/staging استخراج شود. این نسخه noindex دارد و health.json مخصوص همان نسخه را دارد. این ZIP در public_html ریشه استخراج نشود.

۳. phase07-source-update.zip فقط روی کامپیوتر استخراج شود. محتویات online-tarhim-source در همان پوشهٔ مخزن GitHub اضافه/به‌روزرسانی و commit شوند؛ نه در پوشهٔ عمومی هاست. این بسته فقط فایل‌های تغییرکرده/جدید است، نه سورس کامل. فایل‌های src و public موجود تغییری ندارند؛ سه script جدید، package.json و اسناد اضافه/به‌روزرسانی می‌شوند. فایل‌های قبلی و تنظیمات ریشهٔ مخزن حذف یا جابه‌جا نشوند.

۴. بعد از بارگذاری، فقط پایان آپلود را اعلام کنید تا عامل healthcheck دو نشانی https://onlinetarhim.com/ و https://onlinetarhim.com/staging/ را اجرا و نتیجهٔ واقعی را ثبت کند. هیچ رمز یا توکنی لازم نیست بفرستید. نمایش JSON در health.json به‌تنهایی کافی نیست؛ فایل‌های فهرست‌شده هم باید کنترل شوند.

۵. اگر ابزار را روی رایانهٔ خود اجرا می‌کنید، با Node سازگار داخل پوشهٔ پروژه فرمان npm run healthcheck -- https://onlinetarhim.com/ را بزنید؛ برای staging، نشانی پوشهٔ staging را بدهید. خطای manifest مفقود یعنی health.json هنوز در مسیر درست نیست یا سرور آن را ارائه نمی‌دهد؛ checksum متفاوت می‌تواند نشانهٔ آپلود ناقص، نسخهٔ مخلوط، cache یا تغییر محتوا توسط هاست باشد. خطا باید بررسی شود، نه اینکه checksum به‌صورت دستی تغییر کند.

۶. گزارش‌های JSON ابزار فاقد رمز یا دادهٔ بازدیدکننده‌اند. آپلود، پشتیبان‌گیری هاست یا CI از راه دور توسط عامل انجام نشده است. این مرحله صرفاً کنترل زیرساخت استاتیک است و کارکرد واقعی دکمه‌های مراسم، فرم یا پخش را اضافه نمی‌کند.
